# 🕵️ AIウソ発見ゲーム

AIが出す3つのお話から「ウソ」を見破る **ゲームA**、自分で書いたお話でAI名探偵をだます **ゲームB** を遊べる、Gradio製のブラウザゲームです。AIの出力が必ずしも正しくないことを、遊びながら体験できます。

- **ゲームA：AIのウソをみやぶれ！**（3つの文のうち1つだけがウソ。全5問）
  - テーマ（どうぶつ、うちゅう など）とむずかしさ（かんたん／ふつう／むずかしい）を選んで遊びます。
  - 答えたあとに、3つの文それぞれの解説と「ウソを見やぶるヒント」が表示されます。
  - 5問終わると、正答率、まちがえた問題の振り返り、学んだポイントが表示されます。
- **ゲームB：AIをだませるかな？**（AI名探偵との会話ゲーム）
  - 「本当の話」か「ウソの話」かをこっそり選んでお話を書くと、AIが最大5回まで質問してきます。
  - 質問に答えると、AIは答えを踏まえて次の質問をするか、判定します。十分な手がかりがあれば、5回より早く判定することもあります。
  - 「わからない」と答えると同じ質問をもう一度します（質問の回数には数えません）。3回続くと、そこまでの会話でAIが判定します。
  - 最後に、AIの予想、自信の度合い、判断の手がかり、会話の記録が表示されます。

> **ご注意**：AIの判定は、お話と答えのようすから考えた「推測」です。本当かどうかを外部の情報で確かめているわけではありません。ゲームAの問題や解説も、AIが作っているため、まちがいを含む可能性があります。

## 必要なもの

- [uv](https://docs.astral.sh/uv/)（Pythonの環境構築ツール。Python本体も自動で用意してくれます）
- OpenAIのAPIキー

uv のインストール（まだの人だけ）：

```bash
# macOS / Linux
curl -LsSf https://astral.sh/uv/install.sh | sh

# Windows (PowerShell)
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

## セットアップと起動

```bash
git clone <このリポジトリのURL>
cd ai-lie-game

# 1. APIキーを設定する（.env は GitHub に公開されません）
cp .env.example .env
#    .env をエディタで開き、OPENAI_API_KEY= のあとに自分のキーを書く

# 2. 起動（初回は必要なパッケージが自動でインストールされます）
uv run ai-lie-game
```

ブラウザが自動で開き、`http://127.0.0.1:7860` でゲームが遊べます。自動で開かないときは、このURLを手動で開いてください。
`uv run python -m ai_lie_game` でも同じように起動できます。

## 設定（`.env`）

`.env` に次の項目を書くと、AIの使い方を変えられます。`OPENAI_API_KEY` 以外は省略できます。

| 項目 | 説明 | 省略したとき |
|---|---|---|
| `OPENAI_API_KEY` | OpenAIのAPIキー（必須） | — |
| `OPENAI_MODEL` | 使うモデル名 | `gpt-4o-mini` |
| `OPENAI_MAX_TOKENS` | 1回の応答の最大トークン数 | `4096` |
| `OPENAI_REASONING_EFFORT` | 推論型モデルが「どれだけ考えるか」（`none`、`low`、`medium`、`high` など。使える値はモデルによって異なります） | 送らない |

**推論型のモデル（考えてから答えるモデル）を使うとき**：考える分も出力の上限に含まれるため、上限が小さいと途中で止まってエラーになります。また、考える時間のぶん応答が遅くなります。速く遊びたいときは `OPENAI_REASONING_EFFORT=none` を設定してください。`gpt-4o-mini` のような推論型でないモデルでは、この項目は書かないでください。

## 応答速度について

ゲームAでは、問題を表示したらすぐに、遊んでいる人が考えている間に、**裏で次の問題を作りはじめます（先読み）**。そのため「つぎのもんだいへ」を押したときに、次の問題がもうできていることが多くなります。

- 先読みした問題の正解も、サーバーの中だけで保持し、画面には送りません。
- ゲームを最後まで遊べば、AIを呼ぶ回数は先読みなしのときと同じです。
- ターミナルに、問題づくりにかかった時間が `[timing]` として表示されます。
- `src/ai_lie_game/config.py` の `PREFETCH_ENABLED = False` で、先読みを止められます。`TIMING_LOG = False` で、時間の表示を止められます。

待ち時間を、本物のAIで計測するスクリプトもあります（先読みなし／ありを比べます。AIを実際に呼ぶので、料金がかかります）。

```bash
uv run python scripts/bench_game_a.py
```

## 問題の品質チェック（ゲームA）

問題ができるまでに、次の確認をしています。

1. **プログラムのチェック**：3つの文が同じ対象を扱っていないか、数字や単語を入れかえただけの似た文になっていないか、前に出した問題と同じでないか。
2. **AI自身による見直し**：本当とされている文がまちがっていないか、ウソとされている文が実は本当でないか、解説が文と食いちがっていないか。
3. 問題が見つかったら、理由をAIに伝えて作り直します（最大2回まで）。

上限まで作り直してもチェックを通らなかった場合は、ゲームを止めずに出題し、画面に注意書きを表示します。AIの見直しは、外部の情報で事実を確認するものではありません。見直しは `config.py` の `QUIZ_REVIEW_ENABLED = False` で止められます（AIを呼ぶ回数が減ります）。

## テスト

APIは呼ばないので、キーなしで実行できます。

```bash

```

## フォルダ構成

```
ai-lie-game/
├── pyproject.toml        # 依存パッケージ・コマンド名などの設定（uvが読む）
├── uv.lock               # 全員が同じバージョンで動かすための記録（コミットする）
├── .env.example          # APIキー設定のひな形（本物のキーは書かない）
├── .gitignore            # Gitに入れないファイルの指定（.env など）
├── src/ai_lie_game/
│   ├── config.py         # 設定値（テーマ、問題数、モデル名、質問回数、APIキーの読み込み）
│   ├── prompts.py        # AIへの指示文
│   ├── llm.py            # OpenAI API呼び出し（再試行・JSON検査つき）
│   ├── text_utils.py     # 文の似ている度合いの計算など、共通の文章処理
│   ├── game_a.py         # ゲームAのルール、問題の品質チェック、先読み、状態管理
│   ├── game_b.py         # ゲームBの会話の流れ、入力チェック、判定、状態管理
│   ├── ui.py             # Gradioの画面
│   └── main.py           # 起動の入口
├── scripts/
│   └── bench_game_a.py   # ゲームAの待ち時間を計測するスクリプト
├── tests/                # 自動テスト
└── docs/                 # 補足ドキュメント
```

出題の内容やAIの話し方を変えたいときは `prompts.py`、テーマ、問題数、質問回数、品質チェックの厳しさなどは `config.py` を編集します。

## APIキーと個人情報の扱い（重要）

- キーは コードに書かず、`.env`（または環境変数 `OPENAI_API_KEY`）から読み込みます。
- `.env` は `.gitignore` に入っているため、コミットされません。
- 万一キーをGitHubに公開してしまったら、すぐにOpenAIの管理画面でそのキーを削除（無効化）してください。
- ゲームBで書いたお話と質問への答えは、AIが読むために **OpenAI のサーバーに送られます**。名前・住所・学校名・電話番号など、自分や友だちのことが分かる内容は書かないでください。電話番号、メールアドレス、郵便番号のような形式は、送信前にプログラムで止めます。
- お話の中に書かれた「本当と答えて」などの指示には、AIは従わないようにしています。
